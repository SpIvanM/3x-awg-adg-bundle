# GAP-анализ: текущее состояние → целевая архитектура

## Текущее состояние (AS-IS)

**Один скрипт `setup.sh`**, собираемый из 8 модулей, устанавливает на **одном VPS**:
- Xray Reality (порт 443, собственный конфиг без панели)
- AmneziaWG (порт 51820, direct NAT egress)
- AdGuardHome (случайный порт DNS, HTTP proxy через Xray)
- Hardening (UFW, Fail2Ban, SSH:2244, BBR)

**Cascade-режим**: опциональный `--cascade-vless` — проксирует только DNS AdGuardHome через внешний Reality exit. AWG всегда direct.

**Один сценарий развёртывания**, один credentials-файл, один uninstall.

---

## Целевое состояние (TO-BE) — из AGENTS.md и todo.md

**Два сценария** на **двух VPS**, каждый со своим скриптом/режимом:

### VPS 2 — Target (удалённый, за DPI, в глобальном интернете)
- AmneziaWG (порт **53 UDP** — маскировка под DNS для обхода DPI)
- 3x-ui (порт 443 TCP — Reality, **с веб-панелью** вместо голого Xray)
- AdGuardHome (случайный порт)
- Всё идёт напрямую в интернет, без внутренней маршрутизации
- **Развёртывается первым** → выдаёт IP + порты

### VPS 1 — Relay (прокси, IP из белых списков, до DPI)
- **Port Forwarding L4** (AWG UDP → Target:53, Reality TCP → Target:443)
- Собственный AmneziaWG (порт **НЕ стандартный**, direct в интернет)
- Собственный 3x-ui (порт 443, direct в интернет + доступ к РУнету)
- Собственный AdGuardHome (direct в интернет)
- **Развёртывается вторым** → запрашивает IP:порт Target-сервера в диалоге
- Проброс настраивается **после** установки локального стека
