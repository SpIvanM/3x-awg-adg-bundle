2. **Как использовать теги и переменные?**

   - Каждая ВМ в группе получает **тег** из пула `instance_tags_pool`.
   - Этот тег используется в шаблонах IP-адресов: `{ip_{instance.tag}}` и `{external_ip_{instance.tag}}`.
   - В `variables` вы сопоставляете тег с конкретным IP.

---

### ✅ Ответы на ваши вопросы:

#### ❓ Где взять тег?

**Тег — это произвольная строка**, которую вы определяете в `instance_tags_pool`.
Например:

```yaml
instance_tags_pool:
  - vm-a1
  - vm-a2
```

Здесь `vm-a1`, `vm-a2` — это теги. Вы придумываете их сами.

---

#### ❓ Что указать в переменных?

Для IP `84.201.149.73` вы указываете:

```yaml
variables:
  - key: external_ip_vm-a1
    value: 84.201.149.73
```

Если вы хотите, чтобы **все ВМ в группе** имели один и тот же IP (что технически невозможно — один IP = одна ВМ), то, скорее всего, вы хотите **зарезервировать IP и привязать его к одной из ВМ в группе**.

> ⚠️ Важно: **Один публичный IP не может быть одновременно привязан к нескольким ВМ.**
> Вы можете зарезервировать IP и назначить его **одной конкретной ВМ** в группе через тег.

### 🛠 Пример конфигурации (если вы создаёте группу заново):

```yaml
allocation_policy:
  zones:
    - zone_id: ru-central1-a
      instance_tags_pool:
        - vm-a1
        - vm-a2

variables:
  - key: external_ip_vm-a1
    value: 84.201.149.73
  - key: external_ip_vm-a2
    value: 84.201.149.74  # другой зарезервированный IP

instance_template:
  network_interface_specs:
    - subnet_ids:
        - <ваш-идентификатор-подсети>
      primary_v4_address_spec:
        address: "{ip_{instance.tag}}"  # если нужно фиксировать и внутренний IP
      one_to_one_nat_spec:
        ip_version: IPV4
        address: "{external_ip_{instance.tag}}"
```

### 🧩 Что делать прямо сейчас?

Если вы хотите, чтобы **одна ВМ в группе** получила IP `84.201.149.73`, выполните:

1. **Зарезервируйте IP (если ещё не зарезервирован):**

   ```bash
   yc vpc address create --external-ipv4 zone=ru-central1-a --name my-static-ip
   ```

   Или привяжите уже существующий.
2. **Определите тег, например: `vm-main`**
3. **Добавьте в спецификацию:**

   ```yaml
   variables:
     - key: external_ip_vm-main
       value: 84.201.149.73
   ```
4. **Используйте в шаблоне:**

   ```yaml
   one_to_one_nat_spec:
     address: "{external_ip_{instance.tag}}"
   ```

### ❓ Что делать, если группа уже работает?

Если группа уже развернута **без поддержки тегов и переменных**, вы **не можете** просто так добавить фиксированные IP.Вам нужно:

- Пересоздать группу с новой спецификацией.
- Или использовать **отдельную ВМ** с фиксированным IP, если нужен постоянный публичный адрес.
